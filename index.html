01 / WHY THIS EXISTS

能用的节点，
为什么还会白屏？

问题不一定在节点本身。代理软件、TUN 路由和应用本地页面共用一条链路时，任何一个环节的分工不清，都可能让启动画面卡住，或者让语言服务连接失败。

01□

本地页面走错路

localhost、127.0.0.1 和 ::1 本来应该直连，却可能被代理设置影响，导致白屏或加载超时。

LOCAL TRAFFIC / DIRECT
02↗

代理只配置了一半

环境变量、系统代理和本地监听端口可能彼此不一致。脚本会读取候选配置，并实际测试 HTTP 代理是否可用。

PROXY / VERIFY FIRST
03↻

每次都要手工确认

不用再反复寻找安装目录、切换 TUN、试端口。启动器把识别、检测和启动合并成一次操作。

ONE SCRIPT / LESS FRICTION

02 / HOW IT WORKS

三步，把启动链路理顺。

它不是代理软件，也不会接管你的网络设置。脚本只在启动 Antigravity.exe 时，为当前进程准备一套更清晰的连接环境。

03 / CLEAR SCOPE

NO TUN 是目标，
不是夸张承诺。

当本地代理核心提供可用的 HTTP(S) 代理时，Antigravity 可以不依赖 TUN 模式运行。脚本不会关闭、修改或接管你的 TUN 设置。

✓当前包含
  • 自动识别 Antigravity.exe
  • 自动寻找并验证本地 HTTP(S) 代理
  • 为本地地址保留直连路径
  • 兼容 Windows PowerShell 5.1 与 7
  • 不修改系统代理和执行策略
—当前不包含
  • Antigravity CLI 登录
  • 账号、密码或 Token 管理
  • 关闭或配置用户的 TUN 模式
  • 把纯 SOCKS5 代理伪装成 HTTP 代理
  • 替代 Clash、Mihomo 等代理核心
