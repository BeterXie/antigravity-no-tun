01 / WHY THIS SCRIPT

Proxy works.
Antigravity is still blank.

Antigravity can stay blank even when the proxy works. If the proxy also catches localhost traffic, the language service may fail to connect.

01□

Keep local traffic local

localhost, 127.0.0.1, and ::1 should bypass the proxy. If the proxy catches them, the local page can time out or turn white.

LOCAL TRAFFIC / DIRECT
02↗

The app needs a usable HTTP proxy

The script checks environment variables, Windows proxy settings, and common local ports. It uses a candidate only after a real HTTP request succeeds.

PROXY / TEST IT
03↻

Find, test, launch

The script finds the install path, tests the proxy, and starts the app in one run.

02 / WHAT IT DOES

Find the app. Test the proxy. Start Antigravity.

The script sets proxy variables only for the Antigravity process it starts. Your system proxy and TUN settings stay as they are.

03 / SCOPE

NO TUN works when
a local HTTP(S) proxy responds.

The launcher passes the working proxy to Antigravity and keeps local addresses direct. Your TUN settings are left alone.

✓What it does
  • Detect Antigravity.exe automatically
  • Check a local HTTP(S) proxy
  • Keep local addresses direct
  • Run on Windows PowerShell 5.1 and 7
  • Leave system proxy and execution policy unchanged
—The script does not handle
  • Antigravity CLI login
  • Account, password, or token handling
  • Changing your TUN settings
  • Converting SOCKS5 into HTTP
  • Replacing Clash, Mihomo, or another proxy core

START HERE

Run the launcher in PowerShell.

Download the package, extract it, and double-click Start-Antigravity.vbs. The PowerShell script is included.

The VBS launcher uses Windows PowerShell 5.1, so PowerShell 7 is not required. Keep both files in the same folder.

PS>.\Start-Antigravity.ps1
